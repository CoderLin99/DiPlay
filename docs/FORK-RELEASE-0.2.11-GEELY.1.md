# CoderLin99 DiPlay 0.2.11-geely.1

此版本基于官方 **v0.2.11 / versionCode 30**，合入官方发布后的诊断导出修复，以及 `carlito12345/DiPlay` 的吉利适配。

## 来源与改动

- 官方 release 标签：`6014025c653c4dae88d319ce446e0bf1ddb658ea`。
- 用户 fork 原 main：`db3aa9d`，包含发布后的无文件选择器诊断导出修复。
- 吉利适配来源：`carlito12345/DiPlay` 的 `0109cf7`。该 fork 的同名 `v0.2.11` 标签不是官方标签，不作为官方版本基线。
- 集成吉利 OneOS 方向盘按键服务、按键识别及本地配置，覆盖 FX11/G636/KX11 的检测路径；Android 9 KX11 的默认开关遵循来源修复。
- 集成原厂导航/媒体/通话音频路由、Opus 编解码可用性处理、蓝牙 A2DP-sink 交接、旧版 Android 热点接口兼容。
- 集成可选择副屏的 HUD 转向提示投影和诊断信息。**这不是博越 L 完整仪表地图适配**；原有 CarPlay 完整地图输出仍依赖 BYD 显示器选择。
- 保留上游及 carlito 的源码署名，增加本 fork 的源码入口。

## 日志反馈

来源 fork 的报告及方向盘配置原本上传至作者的独立服务器，并非 GitHub。

本 fork 删除该 HTTP 上传器、后台配置上传任务及服务器部署脚本：

1. 设置中填写故障描述，点击“生成 GitHub 故障反馈”。
2. 应用生成脱敏报告，保存到本地；Android 9 或缺少 Downloads 服务时使用应用内部存储及分享功能。
3. 可先查看报告，或将完整 .txt 与反馈链接分享到手机。
4. “打开 GitHub 反馈”进入 `CoderLin99/DiPlay` 的 Issue 编辑页，预填版本、故障描述及有限长度的诊断摘要。
5. 用户登录 GitHub，检查内容，添加完整 .txt 附件并提交。长摘要会截断，完整文件保留在本地。应用不会把打开编辑页当作提交成功。

没有把 GitHub 访问令牌嵌入 APK，也没有匿名上传后端。完整文件的附件上传和 Issue 提交由 GitHub 页面完成。之后可在 Codex 中提供 Issue 编号/链接，让助手读取日志、复现、修复和重新构建；当前没有创建定时监控。

方向盘“保存到本机”只保存映射；可单独导出配置。升级时取消旧 fork 的待执行上传任务，保留本地数据。

## 构建及签名

应用 versionName 为 `0.2.11-geely.1`，versionCode 为 `30`，包名保持 `com.shihab.diplay`。它对应官方 0.2.11，同时通过版本后缀明确标记 fork。

GitHub Actions 的 `Android checks` 工作流可手工运行：先执行单元测试、lint 和 source-only 构建，再构建带运行时认证配置的签名 release APK，验证签名及认证文件内容，打包对应源代码及 SHA-256 校验文件。自动推送检查不会发布 release，也不再自动同步/合并上游。

独立 fork 的 Android 签名密钥与官方签名不同，不能覆盖官方签名的安装。之后本 fork 的版本使用同一密钥更新。私有签名文件保存在本机 `.private/`，并通过 GitHub Actions encrypted secrets 提供给 release 构建；不得提交到源码或随包分享。

实验性 CarPlay 运行时身份来自官方 v0.2.11 APK，下载后按官方 SHA256SUMS 校验。官方 APK SHA-256：`57a3f5daf02af82f636baee26f28a475e04013de8174176c62d97d300498e4c9`。运行时身份按项目原有方式显式提供，只包含在安装包中；源代码压缩包和 Git 均不含该身份及签名材料。

编译和自动测试不能确认博越 L 银河 OS 2.5.0 的私有服务权限、实体按键、音频及副屏实际效果，需要安装后的车辆日志验证。
